Ideogrammar help

How to build an image prompt, give it a look with a style template, and use wildcard lists so every roll is a new variation. Examples marked run live with your own lists.

Generate an image, step by step

  1. Choose the frame. Set the aspect ratio (AR) and size (MP) in the Layout preview header. Choose which model the prompt is for with Showing: Ideogram / Moss in the JSON output; the AI tools follow it too.
  2. Get a starting layout. Either press ✨ Generate prompt and describe the picture (or drop in a reference photo) to have your AI model build it, or build it by hand: write the high-level description, then add elements with ＋ and drag their boxes on the canvas. One element per person; text the image must show goes in a text element.
  3. Give it a look. Click 🎭 Templates, pick one (say Sports video game cover) and press Apply to image. Check the Before/After review and press Apply. The style, background and the people's clothes, pose and lighting are filled in. Fields that came from wildcards get a 🎲 badge.
  4. Roll until you like it. Press 🎲 Roll for new picks. Like one part? Click its 🎲 badge and 🔒 lock that pick; the next rolls keep it. ▾ → Roll ×N and pick shows several versions side by side.
  5. Optional: polish. ▾ → Polish current with AI has your model rewrite the random picks into smooth, consistent wording for Ideogram or Moss. You see a review first, and ↶ undoes it.
  6. Get the image. ComfyUI mode needs a one-time setup: see Rendering with ComfyUI. Manual mode: Copy for Ideogram / Copy for Moss Image (or Download) and paste the JSON into your tool. ComfyUI mode: press Render. To render many variations, set Iterations in the queue and tick Re-roll wildcards each iteration.
  7. Keep it. 💾 saves the setup, wildcard picks included. Once you have a render you like, give the template a picture: 🎭 Templates → 🖼 → Use the current render.
You never have to roll by hand before copying: anything with wildcards that hasn't been rolled yet is rolled automatically when you copy, download or render (▾ → Auto-roll).

Style templates

Working on lists and templates together

  • One window. Lists and templates share one window: lists on the left, templates on the right. 📚 Lists in the header opens it with the templates hidden, 🎭 Templates with both. 🎭 Hide templates / Show templates (bottom of the lists) folds the template side away and brings it back; a template you were editing comes back with your unsaved changes. Closing the template editor (×, Esc or Cancel) discards them.
  • List lookup. Type __ in any field and a list of matching wildcard lists appears as you type (__sho finds clothes/shoes, clothes/sport/shorts…). ↑/↓ to choose, Enter or Tab to insert, Esc to close.
  • Template categories. In 🎭 Templates, ＋ Category makes a category. Each template card (and the editor) has a category menu: pick a category to add it, or (no category) to take it out. An empty category you made shows ✕ to remove it.
  • List categories and subcategories. In 📚 Lists, ＋ sub on a category heading makes a subcategory inside it (e.g. clothes/sport, then clothes/sport/summer — as deep as you like), ＋ list makes a list in it, and clicking a heading folds that level away. ＋ Subcategory at the top does the same for the category of the selected list.

A template is a saved look. It can set these fields:

For the whole imageFor each person / object
Aesthetics (overall look), Lighting, Camera & lens, Medium, Art style, Background, an addition to the high-level description, a colour palette Lighting, Camera, Lens, Wardrobe, Pose, Environment, Mood, Details, plus words before or after the element's description

Any of these can be plain words ("soft window light") or wildcards (__lighting/natural__) that pick something new on every roll. That is what makes one template produce endless variations.

Applying a template

  • Apply to image sets the image fields, and the per-person fields on the element types the template targets (people by default).
  • Apply to selected styles only the elements you selected (click, or Ctrl/⌘-click several on the canvas). Use it to give one person a different look.
  • Each element card has a 🎭 Style & wildcards section with its own template menu, the eight style fields, 🎲 Roll for that element only, and + wildcard to insert a list name where the cursor is.
  • In ✨ Generate prompt → Options, Style template rolls a template and asks the model to build the layout in that style.
  • Applying another template replaces the fields the previous one set. Your own description text is kept.

Making your own

Three ways, from easiest:

  1. 🧭 Template wizard: a guided form, explained below.
  2. Duplicate a template that is close, then Edit it.
  3. ＋ New template: the full editor, including rules and per-format wording.

Sample on any template card shows three random rolls, so you can check a template before using it. Edited built-in templates can be Reset.

The template wizard

The wizard links the wildcard lists to template fields for you, in five steps:

  1. Start. Begin blank, or from an existing template to make your own version of it.
  2. Whole image. The look, lighting, camera and setting of the whole picture. Under each box are suggested lists that fit that field: for Lighting you get __lighting/setups__, __lighting/natural__ and so on. Click one to insert it (shift-click picks two different items). The line under the box shows a sample roll and what it adds to the prompt.
  3. Each person / object. Clothes, pose, mood and so on. These are added to every element the template styles, and rolled separately for each one: two people with Pose = __people/poses__ get two different poses. Each box becomes a labelled sentence after the element's description, so the box you choose is the label the image model sees. If you put a hairstyle list in Lighting, the prompt says "Lighting: buzz cut"; the wizard warns you, and Details is the box for anything without its own. Who / what is the one box for the subject itself (see where the subject goes).
  4. Make things match (optional). See below.
  5. Name & preview. Name, category, a preview image, three sample rolls, then Save or Save & apply to image.

Leave a field empty and the template won't touch it.

Make things match: shared choices

Every list in a field is rolled on its own. A shared choice is rolled once and reused wherever you write its name, so those places agree. It does two jobs:

You want…Do thisResult
Everyone in the same poseShared choice pose = __people/poses__, and Pose = ${pose}Person 1: crouching low · Person 2: crouching low
Everyone in their own posePose = __people/poses__ (no shared choice)Person 1: crouching low · Person 2: hand on hip
Two fields to agreesport = __sports__; look = ${sport} video game cover, Clothes = ${sport} kitthe look and the clothes name the same sport

A shared choice on its own never appears in the prompt, only where you use ${name}. Defining pose = __people/poses__ and also putting __people/poses__ in Pose gives you two separate rolls that won't match. The wizard spots this and offers Use ${pose} there instead. Step 4 also lists every list your fields use, with a one-click Make it match that creates the shared choice and puts it into those fields for you.

Preview images

Each template card shows a picture, so you can see what a template looks like. Templates without one show a coloured placeholder. To set one, press 🖼 on the card:

  • Upload an image…: any picture of the look.
  • Use the current render: the image in the Rendered output window (ComfyUI mode). The usual routine: apply the template, render, then set it as the preview.

To do them all at once, press 🖼 Render previews at the bottom of the templates window. Each template without a preview is applied to the setup you have now, rolled once and rendered with your ComfyUI workflow, and the picture becomes its preview. Start from a simple setup (one person in the middle) so the previews compare fairly. Your setup comes back afterwards; Cancel in the Render tile stops the run. When every template already has one, it offers to redo them all.

Previews are scaled down and kept in the browser. They are included in exports and in folder sync. Some browsers' privacy protection (Brave shields, Firefox "resist fingerprinting", canvas-blocker add-ons) gives the page fake pixels when it shrinks an image, which turns previews into coloured stripes. The editor checks for this; when it happens, a render preview is kept as a link to the image on ComfyUI instead, and an upload is kept as it is (up to 1.5 MB).

Where does the subject go?

Templates set the look. Apart from their cast, they don't create people or boxes. The subject belongs to the layout:

  • Each person or thing is its own element, and its description says who or what it is: "a tennis player mid-serve". One element per person.
  • The high-level description says what the whole picture is: "a tennis player serving on a stadium court".

Three ways to fill them:

  1. Let the AI do it (easiest). In ✨ Generate prompt, describe the subject, and under Options pick a Style template. The model builds the layout and the people in that style.
  2. Wildcards in the description. Write a __people/ages__ __people/roles__ in a person's description. Every roll gives a new subject while the template keeps the look.
  3. In the template. The wizard's Who / what box (step 3) is put in front of each styled element's description, so the template supplies the subject. Leave the description empty, or keep a few words there. Add to the description (step 2) does the same for the high-level description.

Cast: extra elements a template adds

A template can bring its own extras: a referee, a crowd along the bottom, a score graphic in the corner, a passer-by. Add them in the template editor under Cast. Each one has:

  • Name and type (subject, obj, text, logo, bg) and a description, which can use wildcards and the template's ${variables}. Text and logo members also get the words to show and a typography line.
  • Where: left, right, centre, in the distance, foreground, a corner, a band along the top or bottom, the sky, the whole frame, or Anywhere, which picks a new spot every roll.
  • Chance (%) and how many (e.g. 1–3). Every roll decides again whether it shows and how many; the ones not in this roll are switched off, not deleted.
  • Style for this one: its own outfit, pose and so on. Tick Use the template's per-element style too to dress it like the main subjects.

Apply to image adds the cast; applying another template takes it away again. Move, resize or lock a cast element and it is yours: it stays where you put it, stops rolling in and out, and survives a template change. Generate and Improve tell the AI model about the cast, so it doesn't add a second referee. Built-in examples: Sports broadcast (score graphic, opponents), Street photography (passers-by), Concert (crowd).

Improve, Generate, Refine and Render with a template

The template decides how the picture looks (clothes, light, camera, setting) and re-rolls it every time. The AI model decides what is in it and where: who, doing what, and the boxes.

  • ✍ Improve description only rewrites the text in the Generate box. With a style template chosen, it describes the people, what they're doing and where they sit in the frame, and leaves out clothes, light, place and the other things the template rolls.
  • Generate has the model build the layout (elements and boxes) from that text, then links the new elements to the template and rolls it. 🎲 Roll and queue re-rolls keep varying the look.
  • Refine changes the existing setup. Fields the template rolls are put back unless your request is about them: "move her to the left" keeps the rolled outfit, "make her outfit red" keeps the red outfit, and that field stops rolling until you apply the template again.
  • Render sends the setup as it is to ComfyUI. It doesn't use the AI model. Generate & render does both in one go.

Background and description stay in step. When the background is rolled (usually by a template), the high-level description ends with a short "Setting: …" sentence copied from the rolled background, replaced on every roll, so the two never name different places. When a template rolls the background, Generate also strips place and time phrases the model wrote anyway ("in a sunny park", "at night"). Turn this off with Description follows rolled background in the 🎲 menu.

The template owns the look. Applying a template (or Generate with one) also takes out of the descriptions what the template decides: look words ("a candid street photograph of…", "characterized by a Y2K aesthetic", "in the style of…"), places and times when it rolls the background, and clothes when it rolls the outfit. Otherwise those words outvote the template on every roll. The change is shown for review before it's applied. 🖼 Render previews asks what every preview should show, pre-filled with the description cleaned the same way.

Generate's Style template option follows the image's current template unless you pick another, or None.

Keeping subjects out of templates means any template works with any subject. Use Who / what when the template only makes sense with its own subject (e.g. "boxer" for a boxing poster).

Wildcard lists

A wildcard list is a set of options, one per line. Writing its name between double underscores, __colours__, means "pick one line from the colours list". Lists can be in folders: __clothes/hats__. If the name is unique, __hats__ works too.

Open 📚 Lists in the header (or ▾ → 📚 Wildcard lists & rules) to see, edit, add, import or export lists. Lists are grouped in categories (folders): ＋ List makes a list in the selected list's category, the ＋ on a category heading makes one in that category, and ＋ Category starts a new one. To move a list, change its Category and press Save. Click a category's name (the ▸/▾ arrow folds it) to rename it, move it inside another one, or delete it: an empty one just goes; one with lists offers Remove category, keep lists (they move up a level) or Delete category and its lists. Renaming or moving a category updates __category/list__ references in templates, lists and rules. In a list:

# lines starting with # are notes
red
3::navy blue          ← three times as likely as the others
{light|dark} green    ← a line can contain wildcards itself
__colours__ and gold  ← …including other lists

Use 🎲 Sample 10 to see what a list gives. Under the editor it says which templates use the list.

Lists from Stable Diffusion's Dynamic Prompts work as they are. ⬆ Import accepts .txt files (the file name becomes the list name), .yaml / .json packs, or a .zip of a whole wildcards folder.

How lists and templates fit together

📚 list: lighting/natural→🎭 template field: Lighting = __lighting/natural__→🎲 Roll→Lighting: golden hour sunlight

Templates don't contain the options themselves. They refer to lists by name. So:

  • Each template card shows Rolls from: with the lists it uses. Click one to open that list.
  • Edit a list and every template using it changes. Add "neon-lit greenhouse" to places/indoor, and every template that rolls a place can now pick it.
  • To use an imported pack in a template, put its list name in a field: in the wizard pick it from + any list, or type __yourpack/name__ in the editor.
  • You don't need a template to use lists. Type __colours__ straight into any field, such as an element's description, and roll.

Logic: choices, conditions, rules

Random picks can clash (a tennis player in a wetsuit, sunshine at midnight). Three tools keep a roll consistent.

1 · Shared choices (variables)

${name=!…} rolls once and remembers the result. ${name} repeats it anywhere later. In a template these are the shared choices (wizard step 2): they are rolled first and every field can use them.

The sport is picked once and used twice.

Without the ! (${look={moody|bright}}) the choice is rolled again each time it's used. ${name:fallback} uses fallback when nothing is set.

2 · Conditions (guards)

Put [condition] at the start of an option or a list line. That option can only be picked when the condition is true.

The lighting always matches the time.
ConditionTrue when
[time=night]the variable time (or something picked earlier from a list called time) is night
[time=night,dusk]…is night or dusk
[time!=night]…is anything else
[colour~red]…contains "red" (e.g. "dark red")
[sport!=*]no sport has been chosen at all
[a=x & b=y]both are true

If / else: choose the list by a value

Pick a value once with ${a=!{…}}, then give each option a guard. Only the options whose guard is true can be picked, so the value decides which list is used:

${a=!{1|2|3}}{[a=1] __x__|[a=2] __y__|[a=3] __x__ and __y__}

a = 1 picks from x, a = 2 from y, a = 3 one item from each. The value can be a word too, and can come from a template variable (set in the template's Variables, e.g. scene = {beach|city|forest}), so one template can switch whole sets of lists:

One choice decides which list (or lists) the place comes from.

To weight the choice, use weights in the first pick: ${a=!{3::1|1::2|1::3}} makes 1 three times as likely.

The built-in __places/sports__ list uses guards: its lines start with [sport=tennis], [sport=boxing] and so on, so a template that sets sport automatically gets a matching venue. Its last line, [sport!=*] …, covers the case where no sport was chosen.

The venue and kit follow the sport.

3 · Rules

Rules are "if this, then not that" settings that apply to every roll, without changing any list. Edit them in 📚 Wildcard lists → Rules, or inside a template (they then apply only while that template is in use).

When  a pick from list  time-of-day  is  night, midnight, dusk
then from  lighting/natural  never pick  golden hour sunlight, harsh midday sun
  • never pick removes options, only pick keeps just the given ones, always pick forces one.
  • The condition can be a list pick or a shared choice (variable), with is or is not.
  • Values match whole lines, ignoring case; * means "anything", so *sun* matches every line containing "sun".
  • Rules see what was picked earlier in the roll. The image fields roll first, then each element in order.
With the rule “at night, never a line containing sun”.

Unique lists: tick Unique on a list so it never gives the same line twice in one roll (e.g. three people, three different shirts).

Rendering with ComfyUI

To see renders in the editor (and use them as template pictures), the editor has to reach your ComfyUI. Browsers block a page from talking to ComfyUI directly, so the bundled comfy_proxy.py serves the editor and passes requests to ComfyUI.

  1. Start ComfyUI with the Ideogram 4 models the bundled workflow uses.
  2. Start the proxy in the project folder, pointing it at ComfyUI: 
    python comfy_proxy.py --comfy http://127.0.0.1:8188
    Use your ComfyUI's address if it runs on another machine. Alternatively, copy comfy_proxy.env.example to comfy_proxy.env, set COMFY_URL there, and run python comfy_proxy.py.
  3. Open the editor through the proxy: http://localhost:8189/. Not the HTML file directly, and not another web server, or ComfyUI can't be reached.
  4. Switch to ComfyUI mode (top right), leave Connect directly to ComfyUI unticked, and press Test connection.
  5. Pick the workflow in the ComfyUI render panel (below).
  6. Render. The image appears in Rendered output and in the History tile.
  7. Make it a template picture: 🎭 Templates → 🖼 → Use the current render.

History and the prompt beside the render

  • History is its own window: drag it by its title bar, resize it from the edges. The slider in its title bar sets the thumbnail size; the thumbnails fill the window's width.
  • Click a thumbnail to show it in Rendered output. Double-click it (or click the big image) to open the full-size viewer.
  • Tick Prompt in the Rendered output title bar to see, next to the image, the exact prompt that was sent for it: Ideogram or Moss, the workflow, seed and size. Copy copies that exact text, so you can share the image and its prompt together. When the window is narrow the prompt sits below the image.
  • Renders made before this feature show their prompt if ComfyUI still has it (its history, or the prompt saved inside the PNG). Otherwise the panel says prompt not recorded.

Render with your own ComfyUI workflow (e.g. Moss Image)

Ideogrammar can render with any workflow you already use in ComfyUI. The models, sampler, steps and LoRAs stay set in ComfyUI, so there's nothing to re-enter here.

  1. In ComfyUI, open your workflow (e.g. Moss Image text-to-image) and check it renders there.
  2. Use Workflow → Export (API). It saves a .json file. (The normal Save file won't work; it has to be the API export.)
  3. In Ideogrammar, open the ComfyUI render panel, choose Workflow → ＋ Add a workflow from ComfyUI…, and pick the file. You can also drop it on the panel.

Ideogrammar then fills in only four things:

WhatFrom
The promptYour layout, as Moss Image JSON or Ideogram JSON (detected from the workflow; you can change it). It goes into the text encoder that feeds the sampler. If the workflow has a prompt-builder node, Ideogrammar's finished prompt replaces its output.
The sizeAspect ratio + Megapixels: the exact pixel size goes into every node with a width and height (even when they come from a resolution node), and resolution pickers such as Resolution Selector get the same ratio. So you never re-export to change the ratio, and the layout preview always matches the render. Moss-only ratios like 2:1 work here.
The seedSeed / random
How many imagesQueue multiple renders → Iterations

The panel shows where each one goes. If it picked the wrong text box, choose the right one under Prompt goes into. Add as many workflows as you like and switch with the Workflow menu. After changing a workflow in ComfyUI, export it again and use ↻ Replace file.

The proxy also turns on ⇅ Sync with folder for your lists and templates (the wildcards/ folder next to it).

Looking through your renders

Click a render (or a History thumbnail) to open the viewer. ← / → step through them, ▶ Play (or Space) plays them as a slideshow at 2–8 s per image, the mouse wheel, + / − and double-click zoom in (drag to move around), Fit or 0 goes back to the whole image, and 📂 Show in folder opens the folder the file is in. That last one needs the proxy running on this computer; it finds ComfyUI's output folder by itself, or set --output-dir.

Ideogram vs Moss output

Templates and wildcards fill the same editor fields for both models. The exporter places them where each format expects:

Ideogram

"style_description": {
  "aesthetics": "AAA tennis video game box art…",
  "lighting": "stadium floodlights…",
  "photo": "low angle hero shot, 24mm…",
  "medium": "digital composite cover art" },
"elements": [{ "type": "obj",
  "desc": "A tennis player mid-serve. Lighting: hard
   rim light. Camera: low angle. Wardrobe: tennis
   whites. Pose: mid-action swing." }]

Moss Image

"summary": { "caption": "… Style: AAA tennis video
   game box art… Lighting: stadium floodlights…
   Camera: low angle hero shot, 24mm…" },
"items": [{ "label": "character",
  "caption": "A tennis player mid-serve. Lighting:
   hard rim light. Camera: low angle. Wardrobe:
   tennis whites. Pose: mid-action swing." }]

The per-person fields become labelled sentences after the description. Importing either format splits them back into the Style fields. A template can also word things differently for each model (Edit → Per-format overrides), and AI polish uses the guidance for the model you're targeting.

Plain sentences instead of labels

Tick Plain sentences in the JSON panel to drop the labels. The same words then read as a sentence, closer to the captions Moss learned from:

Labels:    A man throwing a punch. Lighting: rim light. Camera: low angle.
           Wardrobe: grey hoodie. Pose: mid-punch. Mood: intense
Sentences: A man throwing a punch. Wearing grey hoodie, mid-punch, intense
           mood, lit by rim light, low angle.

Only Wardrobe (wearing …), Lighting (lit by …), Mood (… mood) and Environment (in …) get a lead-in, and only when the value doesn't already start with one. Everything else is used as written, so for the best result write template fields as phrases: shot from a __camera/angles__ angle on a __camera/lenses__ rather than a bare __camera/angles__. Keep the lists themselves as plain values (low, overhead) so they fit any sentence.

One field for each idea

Some ideas can be set for the whole image and again per element. When a template sets both, the editor and the wizard warn you:

Tags

Moss reads each element's tags as strong labels: a woman tag on a caption about a man draws both. Under the Tags box the editor flags tags that contradict the description (man/woman, child/adult, day/night, indoor/outdoor) and tags the description never mentions, with buttons to remove them or clear all tags.

Recipes

Same person, many outfits

  1. Write the person's description plainly (no wildcards).
  2. In their 🎭 Style section set Wardrobe to __clothes/outfit__.
  3. Roll that element only (its 🎲 Roll), or queue renders with re-roll on.

Magazine cover for a random sport

  1. 🎭 Templates → Magazine cover → Apply to image.
  2. Open the 🎲 badge on Aesthetics and 🔒 lock ${genre} once it says sports.
  3. Roll: the genre stays, and everything else varies.

A crowd where nobody matches

Open clothes/tops in the Wildcard lists, tick Unique, and give each person __colours__ __clothes/tops__. No two people get the same top in one roll.

Night-only city scenes

Fixed to night, with two different practical lights.

Mixing your own pack into a built-in template

  1. Import your pack (e.g. props.txt) in 📚 Wildcard lists.
  2. 🎭 Templates → Duplicate the template → Edit, or open the 🧭 wizard starting from it.
  3. Add {50%? holding __props__} to Details.

Questions

I see __something__ in my prompt. That list doesn't exist (check the spelling in 📚 Wildcard lists; names are folder/name), or Auto-roll is off. A missing list shows a red chip on the template card.

A roll gave nothing for a field. A rule or guard removed every option. The 🎲 badge shows the reason ("Nothing left to pick…").

My edits to a field disappeared after rolling. The field still has a wildcard source. Use Detach, or put your change into the source in the 🎲 badge.

Where are my lists kept? In this browser. Use ⬇ Export for a backup. With comfy_proxy.py running, ⇅ Sync with folder keeps them as files in wildcards/ next to the proxy, editable in any text editor and shareable with other Dynamic Prompts tools.

Do I need an AI model for any of this? No. Templates, lists and rolling work offline. The AI is only used by Generate, Refine and Polish.
